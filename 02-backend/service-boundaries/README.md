# Service boundaries — нарезка сервисов

> Актуальность: сентябрь 2026

## Роль в системе

Где проводить границы модулей и сервисов: по домену, по команде, по изменяемости. Ошибки нарезки дороже выбора ORM.

## Что нужно знать (80/20)

- Modular monolith: модули с явными API внутри одного деплоя
- Микросервис оправдан независимостью деплоя, масштаба или команды — не «для чистоты»
- Связность: shared DB, sync calls, события — разные цены
- Контракты между границами версионируются; внутренности — нет
- Обратные вызовы и распределённые транзакции — запах; saga/outbox — осознанный паттерн

## Развилки

| Развилка | О чём спор (одна строка) |
| --- | --- |
| Module vs network service | Простота транзакций vs изоляция сбоев и деплоя |
| Shared DB vs DB per service | JOIN и consistency vs независимая эволюция |
