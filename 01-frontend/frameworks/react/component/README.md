# Component — React-компонент

> Актуальность: сентябрь 2026

## Роль в системе

Базовая единица UI в React: описание куска интерфейса как функции от props/state. Архитектурно компонент — граница ответственности и переиспользования, не «файл с JSX».

## Что нужно знать (80/20)

- Компонент = UI + локальное состояние + явный контракт props
- Однонаправленный поток данных: props вниз, события вверх
- Разделение: presentational vs container / «глупые» vs «умные» (идея, не догма)
- Границы: что входит в компонент, а что — в hooks/сервисы/data layer
- Ключи списков, контролируемые инпуты, поднятие state
- Server vs Client Component: где можно эффекты, браузерные API, секреты
- Стоимость ре-рендеров: когда мемоизация оправдана, а когда преждевременна
- A11y и семантика — часть контракта компонента, не внешний слой «потом»
- Тестировать поведение через роли/текст, не через детали реализации

## Развилки

| Развилка | О чём спор (одна строка) |
| --- | --- |
| Толстый компонент vs hooks + тонкий UI | Локальность vs переиспользование логики |
| Много мелких компонентов vs несколько крупных | Переиспользование vs читаемость фичи |
| Client island vs Server Component | Интерактивность и браузерные API vs меньше JS |
