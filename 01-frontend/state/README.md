# State — состояние на клиенте

> Актуальность: сентябрь 2026

## Роль в системе

Где живёт правда о UI и данных на клиенте. Неверная модель state — источник лишней сложности, рассинхрона с сервером и «проп-дриллинга».

## Что нужно знать (80/20)

- Типы state: **локальный UI**, **серверный кэш**, **URL**, **глобальный клиентский**, **форма**
- Большая часть «глобального Redux» часто = server cache (React Query / TanStack Query и аналоги)
- Подъём state вверх ровно настолько, насколько нужен общий доступ
- URL как источник истины для фильтров, пагинации, шаринга
- Избегать дублирования server state в клиентском store без причины

## Дочерние узлы

Запланировано: local-vs-global, url-state, form-state, client-stores.

## Развилки

| Развилка | О чём спор (одна строка) |
| --- | --- |
| Server cache library vs global store | Данные с API vs чисто клиентский UI-state |
| Context vs dedicated store | Простота vs производительность и DevTools |
