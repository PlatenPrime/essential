# Architecture styles — стили архитектуры

> Актуальность: сентябрь 2026

## Роль в системе

Как нарезаны **границы** системы: один деплой или много, синхронные вызовы или события, общий ли процесс. Стиль задаёт операционную модель сильнее, чем выбор фреймворка.

## Что нужно знать (80/20)

- **Monolith** — один деплой, общие границы в коде
- **Modular monolith** — один деплой, жёсткие модульные границы (частый дефолт 2026)
- **Microservices** — независимые деплои, сеть между сервисами, распределённые сбои
- **BFF** (Backend for Frontend) — API, подогнанный под конкретный клиент
- **Event-driven** — слабая связность через события/очереди, eventual consistency
- Понимать: стиль выбирают по команде, домену и операционной зрелости, не по моде

## Развилки

| Развилка | О чём спор (одна строка) |
| --- | --- |
| Modular monolith vs microservices | Скорость команды vs независимое масштабирование и изоляция сбоев |
| Sync orchestration vs events | Простота трассировки vs слабая связность |
| Shared DB vs DB per service | Транзакции и простота vs независимость эволюции схемы |
