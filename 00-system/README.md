# System — позвоночник веб-проекта

> Актуальность: сентябрь 2026

## Роль в системе

Общая модель: из каких слоёв состоит веб-приложение, как проходит запрос, какие стили архитектуры существуют и какими атрибутами качества меряют решения. Без этой карты остальные разделы — список технологий без контекста.

## Что нужно знать (80/20)

- Веб-проект — это **система слоёв**, а не «фронт + бек»
- Понимать **путь запроса**: браузер → CDN/edge → app → API → данные → ответ
- Отличать **стиль архитектуры** (как нарезаны границы) от **стека** (на чём написано)
- Уметь называть **атрибуты качества**, которыми платят за каждое усложнение: latency, consistency, cost, complexity, operability
- Знать, что «масштабирование» и «микросервисы» — не синонимы
